INFERENCE ENGINEERING:
Inference basically means from the moment u give a prompt , to the moment say a response comes back , many things happen ,promots hit a gpu server(if multiple , then we must load balance) , then say we hit the gpu server , then we  have the model , now the model in itself must be fast enough , how do we make it fast enough , through KV caching , quantization(wont make fast , but mem efficient to load in servers), speculative decoding -> these are techniques to make llm faster .
But what is an inference engine then say 100 requests come at the same time , how to distribute the requests , how to batcht he requests , and send it to which gpu , kv cache management

Speculative Decoding -> first u want to increase latency of a large llm , so u  use a draft llm(small ll) to generate some draft tokens(say k draft tokens), now the large model appends these draft tokens with the original context ,and does forward pass and  finds probabilities , and then is the process of accepting or rejecting draft tokens,(based on comparison of draft token probab and  large model token probab), say N of them are accepted but in the process 1 more token will be generated by  the large model so N+1  tokens generated instead of 1.

Latency vs Throughput - latency is imp for online jobs , while throughput for offline jobs
TTFT-Time to first token->latency metric 
TPS- token per second->throughput metric
these are good for online jobs
Prefill vs Decode ->When u type a prompt , first the prompt needs to be processes , its attention needs to be calculated , kv cache needs to be set up , that phase is called prefill and TTFS is an indicator to prefill , while after first token is done , now time is to decode , this is related to TPS .
prefill is compute bound while decode is memory bound
in prefill u are doing a lot of computation
in decode , ultimately u are generating just 1 token ,  a lot of time goes into accesssign memory

Does Quantization help in reducing latency?
In decode phase (as uk from beforehand quantization will reduce memory footprint) ,now in decode phase  imagine moving a 14gb model weights from hbm to sram ,compared to 7gb ,now memory access takes time , so yeah , it will reduce latency
In prefill phase , since model weights are quantized , operations now happend in tensor cores dealing with operations in  lower precision ,so latency does reduce
